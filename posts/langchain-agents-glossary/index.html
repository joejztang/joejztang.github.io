Langchain agents glossary

November 23, 2026 7-minute read
Langchain • Langgraph • Agentic

This is a directly copy of content of a langchain course.

Table of Contents

  • Agent Development Lifecycle (ADLC): The iterative practice of building, testing, deploying, and monitoring an agent, with governance wrapping around all four phases. The strongest teams cycle through these phases quickly and systematically so that production behavior feeds directly into the next round of Build and Test work. See The Agent Development Lifecycle.

  • Annotation Queue: A queue in LangSmith where human reviewers label agent outputs, for example scoring responses as correct or incorrect. Annotation queues are used to collect human feedback that can then be used to align and improve LLM-as-Judge evaluators. See Improve LLM-as-judge evaluators using human feedback.

  • Clustering: The process of grouping similar items together based on shared characteristics. In AI evaluation, clustering is used to organize failures, user queries, or agent behaviors into meaningful categories. (Anthropic, 2024). Cemri et al. (2025) cluster multi-agent system failures into a taxonomy of 14 failure modes across 3 categories. Clustering is a key technique for scaling failure analysis beyond what manual review can handle.

  • Code-based Evaluator: An evaluator implemented as a deterministic function — no LLM calls involved. Code-based evaluators check concrete, verifiable properties such as whether a specific tool was called, whether the output matches an expected format, or whether a keyword is present.

  • Dataset: A collection of examples in LangSmith used for evaluation. Each example contains inputs (e.g. a user question) and optionally reference outputs or metadata. Datasets are versioned and can be reused across experiments.

  • Evaluation: The process of systematically measuring an agent’s performance against a dataset. In LangSmith, an evaluation runs your agent on every example in a dataset, applies one or more evaluators, and records the results as an experiment.

  • Experiment: The recorded result of running an evaluation — one pass of your agent over a dataset, scored by evaluators. Each experiment captures the inputs, agent outputs, evaluator scores, and metadata for every example. Experiments are the unit of comparison in LangSmith: you compare experiments across iterations to see whether a change to your agent improved or degraded performance.

  • Evaluator: A function that scores an agent’s output for a given dataset example. Evaluators can be code-based (deterministic checks like verifying tool usage) or LLM-based (using a judge model to assess quality). They return a key, score, and optional comment.

  • Failure: A single instance where a system, component, or agent produces an output or behavior that does not meet its requirements or expectations. In testing, a failure is the observable symptom — the thing you catch in an eval. Example: an agent returns an incorrect date in a structured report.

  • Failure Mode: A category that describes how a system or agent can fail, rather than a single instance of failure. Borrowed from FMEA (Failure Mode and Effects Analysis), a failure mode groups individual failures by their nature or cause. In AI/agent evaluation, identifying failure modes helps teams design targeted evals and prioritize improvements. Examples: hallucination, instruction non-compliance, incorrect tool selection, output format violations. A single failure mode may account for many individual failures across many test runs.

  • Ground Truth: The known correct answer or label for a given input, used as the standard against which a system’s output is compared. In agent evaluation, ground truth is typically provided as reference outputs in a dataset — for example, the expected SQL query, the correct extracted date, or the ideal response. Ground truth enables reference-based evaluation and is essential for computing confusion matrix metrics (TP, TN, FP, FN). Not all evaluations have ground truth; reference-free evaluations assess quality without it.

  • LLM-as-Judge Evaluator: An evaluator that uses a language model to score or grade an agent’s output. A prompt describes the evaluation criteria and the LLM returns a judgment (score, label, or explanation). LLM-as-Judge is useful when the quality dimension is subjective or hard to capture in code — for example, helpfulness, tone, conciseness, or factual correctness. The term was coined by Zheng et al. (2023) in “Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena”, which demonstrated that GPT-4 used as a judge could match human preferences with over 80% agreement — comparable to inter-human agreement. (Zheng et al., 2023, Section 3, pp. 4–6; Ito et al., 2025, Section 4.4.3)

  • Offline Evaluation: Evaluation performed on a fixed dataset before or outside of production. The agent is run against a curated set of examples, and its outputs are scored by evaluators. Offline evaluation is repeatable, controlled, and well-suited for regression testing, comparing experiments, and catching known failure modes. In LangSmith, this corresponds to running an experiment against a dataset. Offline evaluation is the core activity of the Test phase of the ADLC. The tradeoff is that it can only test scenarios you’ve anticipated: it won’t catch failures on inputs you haven’t seen yet.

  • Online Evaluation: Evaluation performed on live production traffic as the agent serves real users. Rather than running against a fixed dataset, online evaluation scores actual agent responses in real time (or near-real time). This catches failures that offline evaluation misses: novel user inputs, edge cases, and distribution shifts. In LangSmith, online evaluation can be implemented by applying evaluators to production traces via rules or automation. Online evaluation is a core activity of the Monitor phase of the ADLC. Online and offline evaluation are complementary: offline evaluation gates what you deploy, online evaluation observes what’s deployed.

  • Prompt: The instruction or template given to a language model that defines its task and behavior. In agent evaluation, the prompt plays a dual role: it drives the agent’s behavior (the system prompt), and it also defines evaluation criteria when used in an LLM-as-Judge evaluator — where the prompt tells the judge model what to assess and how to score.

  • Reference-based Evaluation: Evaluation that compares a model’s output against human-written gold-standard references to assess quality. The reference serves as the “correct” answer, and metrics measure how closely the output matches it. In agent evaluation, this means having expected outputs in your dataset to compare against. (Ito et al., 2025, Sections 1–2)

  • Reference-free Evaluation: Evaluation that assesses output quality without gold-standard references. Instead, quality is estimated through other proxies such as correspondence between input and output, learned models of human judgment, or LLM-as-a-judge. Reference-free approaches are especially valuable for open-ended tasks where there is no single correct answer. Most LLM-as-Judge evaluators are reference-free. (Ito et al., 2025, Sections 1–2)

  • Regression: A previously passing behavior that now fails after a change to the agent. Regression testing means re-running your evaluations after each change to verify that nothing that used to work has broken. In LangSmith, you detect regressions by comparing experiments — if a score drops on examples that previously passed, that’s a regression.

  • Run (Span): A single operation within a trace — one discrete step your application performed. Each run has a run_type (e.g. llm, chain, tool), inputs, outputs, timing, and token/cost metadata. Runs can be nested: a parent run can have child runs, forming the tree structure you see in the LangSmith trace viewer. The terms “run” and “span” are interchangeable in LangSmith — “span” aligns with OpenTelemetry terminology, while “run” is the LangSmith-native term. See Run (span) data format in the LangSmith docs.

  • Thread: A multi-turn conversation between a user and an agent, composed of multiple traces linked by a shared thread ID. Each turn in the conversation produces its own trace, and the thread groups them into a single conversational session. The full hierarchy in LangSmith is: a thread contains traces, a trace contains runs (spans). See Configure threads in the LangSmith docs.

  • Trace: The complete record of a single request through your application, from input to output. A trace captures every step your agent takes to handle one invocation — all the LLM calls, tool calls, retrieval steps, and intermediate processing. A trace is composed of one or more runs (spans) organized in a parent-child tree. The root run’s ID is also the trace ID. See Traces in the LangSmith docs.
